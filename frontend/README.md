# CRM ИТ Школы Ростелекома — фронтенд

React 19 + Vite. Интерфейс по дизайн-системе Ростелекома (Атомаро): токены, шрифт Rostelecom Basis, кнопки и иконки из `@atomaro/*`, доступные примитивы (диалоги, меню, поповеры) — из Base UI.

```bash
npm run dev      # http://localhost:5173
npm test         # юнит-тесты доменной логики (node:test, без зависимостей)
npm run build    # продакшен-сборка в dist/
```

Демо-вход: на экране входа выберите роль. Данные демо-стенда хранятся в localStorage; «Справка → О системе → Сбросить демо-данные» возвращает исходное состояние.

## Структура

```
src/
  app/        корень приложения, hash-роутер, таблица маршрутов с правами
  auth/       сессия и текущая роль (в продуктиве — Keycloak / OIDC)
  domain/     чистая бизнес-логика без React: этапы и сроки, фильтры, отчёты,
              аналитика, импорт, роли, коды ошибок — покрыта тестами
  data/       демо-данные; структура повторяет db.sql
  store/      состояние: reducer, действия с проверкой прав, селекторы, кэш в localStorage
  ui/         переиспользуемые компоненты дизайн-системы (кнопки, поля, таблица, графики…)
  layout/     каркас: навигация и мобильная шапка
  features/   экраны, сгруппированные по разделам продукта
              features/legacy — экраны прежнего дизайна из ветки main (дашборд и импорт)
              на адресах /main/*, старый styles.css изолирован под класс .legacy
  lib/        инфраструктура: хранилище, экспорт XLSX/XLS/PDF/PNG, чтение XLSX
  styles/     токены (цвет, типографика, отступы) и базовые стили
tests/        юнит-тесты domain/ и lib/
public/help/  скриншоты для встроенной справки
```

## Принципы

- **Слои.** `domain` не знает о React и хранилище; `store/useActions` проверяет права и бизнес-правила; компоненты только показывают данные и вызывают действия. При подключении бэкенда меняется слой `store`, экраны остаются прежними.
- **Стили.** CSS Modules рядом с компонентом, значения — только из `styles/tokens.css`. Контраст текста — не ниже WCAG AA.
- **Ошибки.** Все ошибки пользователя — `AppError` с кодом из `domain/errors.js`; код виден в интерфейсе и описан в справке.
- **Без перезагрузок.** Изменения применяются мгновенно; перевод этапа, комментарий и правки можно отменить из уведомления.
- **Кэш действий.** Фильтры, вид списков и черновики комментариев сохраняются между визитами.
- **Адаптивность.** Все экраны работают от 360 px: таблицы превращаются в карточки, диалоги — в нижние листы.
- **Экраны main.** Раздел меню «Экраны main» — дашборд и импорт прежнего дизайна, сохранённые без изменений: разметка и классы из `main.jsx` ветки main, стили из её `styles.css`, изолированные под `.legacy`. Новые экраны и токены он не затрагивает.

## Требования ТЗ → где реализовано

| Требование | Где |
| --- | --- |
| Визуализация пути, переходы, комментарии, файлы | `features/interactions/*` |
| Создание и изменение workflow, переименование статусов | `features/workflows/WorkflowsPage.jsx` |
| Фильтрация за период по вузам, направлениям, продуктам, ответственным | `features/filters`, `domain/filters.js` |
| Статистика, графики, выгрузка PNG/PDF | `features/analytics`, `ui/charts` |
| Отчёты XLS/XLSX/PDF по выбранным колонкам | `features/reports`, `lib/export` |
| Каталоги и импорт xls/xlsx по маппингу полей | `features/catalogs`, `domain/import.js`, `lib/xlsx` |
| API LMS и сайта (JSON) → существующий или новый workflow | `features/integrations` |
| Ролевая модель и ограничение видимости данных | `domain/roles.js`, `features/admin/UsersPage.jsx` |
| Коды ошибок | `domain/errors.js`, «Справка → Коды ошибок» |
| Встроенная документация со скриншотами | `features/help` |
